## 意图锚点（成璐原话，2026-11-07）

> "那有人做过 icl 和权重的极限吗，假设控制其他变量，权重保持和 icl 一样的单变量增量（例如一个 base，微调不同类似 icl 注入知识大小的知识）。或者我猜这是显然的，权重路线更固化、熟练、稳定，icl 则低成本换性能下降。但这个 pareto 函数有吗？然后可以如何指导 icl 的上限？"

本任务把三个问题变成有判决的文献结论：
1. **有没有人做过受控的单变量对照**——同一 base，ICL demo 量 K 与微调数据量 D（或参数更新量 ΔW）按"等价知识量"对齐，测两条曲线的形状与交点？
2. **"权重固化/稳定、ICL 便宜但降质"这个直觉在多大程度上成立**——逐条找证据支持或反驳，不允许整体打包接受。
3. **Pareto 前沿存在吗，形式是什么，能否推出 ICL 的可操作上限**。

## 子问题

### Q1: 受控单变量对照是否存在

- 搜索组合：in-context learning vs fine-tuning controlled comparison same model；knowledge injection parameter update vs prompt tokens matched; "ICL vs LoRA" / "ICL vs SFT" head-to-head benchmark；few-shot prompting vs fine-tuning data efficiency frontier；test-time compute vs training compute knowledge transfer。
- 判据（什么才算合格的对照）：同一 base 模型 + 知识量单一变量（demo 数 K ↔ 微调样本数 D 或 epoch×lr 等效参数量 ΔW）+ 其余变量受控（评测集相同、温度/解码相同）。
- 判决分类：(a) 完全合格对照存在 → 列出 ≥3 篇，给曲线形状描述；(b) 只有部分对照（如只比了准确率没比 token 成本）→ 说明缺哪一维；(c) 不存在 → 给出穷尽 query 记录。
- **特别注意**：很多"ICL vs FT"论文实际是跨模型比较或不同任务家族比较，不算受控对照——必须逐条甄别，把不合格的单独归类并说明为什么不适用。

### Q2: 三条直觉断言逐条核验

对每条给判决（成立/部分成立/不成立/证据不足）+ ≥2 条独立来源：

- **C1「权重路线更固化」**：微调后知识是否真的更难被覆盖/遗忘？找证据：灾难性遗忘方向（微调新知识后旧能力衰减）、以及反向的"prompt 知识可被后续 context 覆盖而权重知识不可"的实验。
- **C2「权重路线更熟练」**：同一知识经微调 vs 经 ICL 调用，下游任务准确率差异有多大？效应量随任务复杂度的变化？（注意区分"知识本身"与"调用知识的推理"——可能知识都在，差在调用。）
- **C3「ICL 低成本换性能下降」**：成本要拆成 (a) 每 token 推理成本（context 长度 × 价格）vs (b) 一次性微调成本（GPU 时 × 价格）。找有没有人算过**交叉点**：知识量 K 超过多少时微调总成本反超 ICL？性能差距是否随 K 单调扩大还是存在饱和？

### Q3: Pareto 前沿的存在性与形式

- 定义坐标轴：x = 知识量 K（统一度量，优先用 token 数或样本数，两轴都报）；y = 质量（任务准确率）；第三维 = 总成本（推理 token 成本 + 训练成本）。
- 搜索：有没有论文显式画出两条曲线（ICL(K) 与 FT(D)）在同一坐标系下的对比图？有没有人拟合过函数形式（幂律/对数/saturating）？
- 判决：(a) 前沿存在且有函数形式 → 抄录公式 + 适用范围；(b) 前沿存在但只有散点 → 给出散点分布描述 + 可拟合的形式猜测（标 conf）；(c) 不存在 → 指出缺哪一维的数据。
- **关键区分**：性能 Pareto（质量-成本平面）与容量 Pareto（知识量-保持率平面，即新学 K 的同时旧能力掉多少）是两个不同的前沿，分别报告。

### Q4: ICL 上限的可操作推导（写作用）

- 从 Q1-Q3 的判决出发，推导 ICL 上限的**条件依赖**：上限不是常数，它是 f(task complexity, K, context window, 知识类型[事实/程序/偏好])。找出哪些条件下界已被证明（引用 T-PR-09 的 1/√(nT) 与 2602.02909 的下界实验）。
- 给出**可操作的判断准则**（一段可直接引用的文字）：什么情况下该用 ICL、什么情况下该转微调——以"知识量 K 相对模型容量 N 的比值"和"任务是否要求知识被高频复用"为两个主轴。
- 与 compression-unified-view 的关系（**2026-11-08 修正**）：ICL 不是"解压信息量上界"——那是把推理侧的解压比喻错安到了 ICL 头上。正确框架：ICL = 在线学习，受两个独立约束——(a) **容量下界**：窗口内 demo 信息量 K_demo 必须 ≥ 任务概念最小描述长度 K(concept)，低于此值学不出来（编码/压缩视角，对应你说的"多大窗口允许完美临时学习"）；(b) **有效跨度上界**：名义窗口 ≠ 有效注意力跨度（T-PR-10 M2：Jamba 256K→有效 4K），超过有效跨度后多塞的 demo 不产生额外学习收益（检索/注意力视角）。所以 ICL 上限 = min(容量墙, 有效跨度墙) × 泛化率(1/√(nT))。**找证据支持或反驳"有效跨度是 binding constraint"这个推论——若成立，当前所有'长上下文 ICL'工作都在用错分母算上限，是系统性盲区。**
